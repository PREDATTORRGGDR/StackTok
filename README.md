# StackTok

Минималистичный десктопный клиент для нескольких аккаунтов TikTok: изолированные сессии, публикация видео через сайт TikTok, очередь и планировщик. Интерфейс — только на русском.

## Команды

```bash
npm install
node node_modules/electron/install.js   # если npm заблокировал postinstall и Electron не скачался
npm run dev          # запуск в режиме разработки
npm run typecheck    # проверка типов
npm test             # unit-тесты (vitest)
npm run build && npm run test:e2e   # e2e на МОК-сайте (без сети и без реального TikTok)
npm run dist         # установщик Windows -> release/StackTok Setup <версия>.exe
```

## Архитектура

- **Electron + React + TypeScript + Vite** (electron-vite), иконки Lucide. Без бэкенда.
- **Сессии**: у каждого аккаунта собственный persistent-раздел `persist:acct-<id>` (cookies, localStorage, IndexedDB, кэш). Окно TikTok — отдельный `WebContentsView` без Node и preload, изолированный от интерфейса.
- **Автоматизация**: Playwright сознательно не используется — он не делит сессии с Electron и потребовал бы второй набор логинов. Загрузка идёт в скрытом окне **того же раздела** через Chrome DevTools Protocol (`webContents.debugger`), поэтому повторный вход не нужен. Селекторы TikTok Studio собраны в `src/main/uploader.ts` (`SELECTORS`).
- **Хранилище**: один JSON-файл (`stacktok.json`, атомарная запись, валидация при загрузке). Паролей и cookies там нет; cookies не покидают основной процесс.
- **Очередь**: статусы draft → scheduled → ready → uploading → published / failed / awaiting_user / needs_verification / cancelled; недопустимые переходы запрещены (`src/shared/logic.ts`).

## Правила надёжности

- «Опубликовано» ставится только при наблюдаемом подтверждении (переход в менеджер контента или сообщение на странице). Иначе — «Нужна проверка».
- Как только нажата кнопка публикации, задача помечается `submitted` и **никогда не повторяется автоматически**. Прерванная после этого задача тоже идёт на проверку.
- В одном аккаунте не бывает двух загрузок одновременно; параллелизм между аккаунтами настраивается (1–3).
- Капча, проверка безопасности, истёкший вход, изменившаяся вёрстка — автоматизация останавливается, открывается окно, задача ждёт вас («Продолжить»). Обход защиты не реализован.
- Планировщик работает, только пока приложение открыто. Задачи, чей срок прошёл при закрытом приложении, помечаются «Просрочено» и сами не запускаются.

## Данные и резервные копии

Папка `%APPDATA%\stacktok` (путь также виден в Настройках → «Открыть папку»): `stacktok.json` и `Partitions\` с профилями аккаунтов. Для копии закройте приложение и скопируйте папку целиком; в ней сохранены входы — храните её приватно. Удаление аккаунта оставляет профиль на диске, если явно не выбрать «удалить данные сессии».

## Что проверено

- Unit-тесты: хэштеги, время, автомат состояний, очередь, восстановление после перезапуска, валидация хранилища.
- E2E на моке (`tests/e2e.mjs`): запуск, добавление/удаление аккаунтов, раздельные cookie и папки профилей, сохранение после перезапуска, пресеты, несколько аккаунтов → отдельные задачи, планирование, «нет подтверждения → нужна проверка», запрет повтора после нажатия, капча → пауза → продолжение, истёкшая сессия, просроченные задачи.
- Сборка установщика Windows и запуск упакованного приложения.

## Ограничения

- **Реальная публикация в TikTok не проверялась**: нужен аккаунт и контролируемый тест. Селекторы и признаки подтверждения основаны на текущей структуре TikTok Studio и могут устареть; при несовпадении задача уходит на ручное продолжение.
- Страница загрузки в iframe не поддерживается (задача встанет на паузу).
- Встроенный TikTok может блокировать часть функций Electron — есть кнопка «Открыть в браузере».
- Установщик не подписан и без собственной иконки.
- Определение имени аккаунта — по ссылке профиля на странице; всегда требуется подтверждение пользователем.
